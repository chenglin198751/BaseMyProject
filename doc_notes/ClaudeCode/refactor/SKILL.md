# 代码重构

## 重构原则

重构本质：**改善代码内部结构，不改变外部行为**。

---

## 修改范围限制（强制）

- 仅允许修改当前指定文件
- 禁止修改其他文件
- 禁止假设其他文件会同步变更

---

## 修改约束（关键）

- 禁止修改任何 public API（class / method / 返回值 / 字段 / 常量）
- 禁止引入新的依赖库
- 非必要不可删除注释（可以修改或新增注释）
- 修改后必须保证代码行为一致（包括边界条件和异常处理）
- 如果不确定修改是否安全，则不要修改

---

## 执行流程（强制）

必须严格按顺序执行：

1. 识别并列出 public API
2. 分析代码问题
3. 制定修改方案
4. 在确认安全的前提下执行修改（apply_patch）

如果无法确认修改安全，则停止修改并说明原因。

---

## 输出要求（四阶段）

必须按以下结构输出：

### Public API
列出当前代码的 public API

### 问题分析
- 当前代码问题
- 潜在风险
- 不合理设计

（避免过多实现细节）

### 修改思路
- 做什么修改
- 修改目的

（可提及方法名/变量名，但不贴大段代码）

### 执行结果
- 实际完成的修改
- 是否修复 bug
- 是否存在未处理风险
- 必要时可附少量关键代码片段（可选）

---

## 执行过程限制

- 不允许边修改边解释
- 不允许输出中间修改内容
- 必须在修改完成后统一输出
